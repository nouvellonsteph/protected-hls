# Agent guide

This file gives coding agents the minimum context needed to change this repository safely.

## Project intent

This is a demonstration of protected HLS delivery and authenticated live HLS ingest on Cloudflare. It is not a general media platform or a production authentication service.

The UI has two stable walkthroughs:

- Part 1 demonstrates `hdnts` to `hdntl` exchange and viewer-specific HLS rewriting over private canonical R2 objects.
- Part 2 demonstrates managed or external primary/backup HLS contribution, complete-manifest publication, atomic source promotion behind a stable viewer URL, and protected live playback.

## Non-negotiable invariants

- Authorize a media request before reading R2 or shared cache.
- Never persist or shared-cache viewer-specific rewritten playlists.
- Strip viewer authorization and CMCD fields from canonical upstream cache keys.
- Keep segment request bodies out of the Durable Object; stream them directly to R2.
- Record every referenced segment before publishing a media playlist.
- Preserve the pending-generation and conditional-R2-write recovery protocol.
- Commit canonical R2 generations inside the coordinator concurrency fence and keep generation numbers monotonic across resets.
- Change the active source only when its canonical R2 generation is committed or recovered.
- Keep primary and backup media under source-qualified immutable paths so in-flight viewers can finish old requests after a switch.
- Keep publisher tokens scoped to one source, event, rendition, and expiry.
- Never log `hdnts`, `hdntl`, raw signing secrets, ingest secrets, or publisher URL tokens.
- Do not expose Part 2 control routes without administrative perimeter protection.
- Do not commit customer names, account IDs, domains, resource IDs, secret values, local state, generated media, or screenshots.

## File map

- `src/index.ts`: Worker entry point, routing, token exchange, delivery, and source inspector.
- `src/token.ts`: token format, HMAC signing, validation, ACL and time policy.
- `src/hls.ts`: recursive URI rewriting, playlist tailing, and projected live windows.
- `src/source-role.ts`: primary/backup role validation and default publication arbitration.
- `src/part2.ts`: ingest protocol, R2 publication, external publisher credentials, and paired container operations.
- `src/stream-coordinator.ts`: Durable Object SQLite schema and publication state machine.
- `src/live-publisher-container.ts`: container definition and internal ingest service binding.
- `container/`: disposable FFmpeg source using native HTTP PUT plus a small health endpoint.
- `ui/src/`: React UI. Preserve its established visual language unless a task explicitly requests design changes.
- `tests/`: characterization tests for pure token, HLS, and MediaLive behavior.
- `wrangler.jsonc`: generic binding contract only; public release configuration must not contain real account resources.
- `worker-configuration.d.ts`: generated by Wrangler. Do not edit it manually.

## Commands

```sh
npm ci
npm run types:check
npm run check
npm test
npm run build
npm run deploy:dry-run
```

Use `npm run verify` for the standard gate. Run `npm run types` after changing `wrangler.jsonc`, then include the regenerated declaration in the same change.

For UI development, use `npm run dev`. For full local API development, build the assets and run `npm run dev:worker` in a second terminal.

## Change discipline

- Read the complete affected files before editing.
- Prefer the smallest behaviorally correct change.
- Do not add compatibility branches without a demonstrated consumer or persisted-data need.
- Keep request bodies streamed when their size is unbounded or media-sized.
- Await, return, or explicitly handle every Promise.
- Use Web Crypto and cryptographically secure randomness for security-sensitive values.
- Keep request-scoped state out of module globals.
- Add tests for token formats, URI rewriting, ingest paths, and publication-state changes.
- Do not alter UI copy, structure, or styling as a side effect of backend maintenance.

## Configuration and secrets

The committed Wrangler file is safe by default: it has no route, disables `workers.dev` and previews, uses generic resource names, and declares required Worker secret names without values.

Never commit customer-specific resource values in a public branch. Keep secret values in ignored `.dev.vars`, Wrangler Worker secrets, or CI secret channels.

Token-bearing paths require log redaction. Do not enable full request URL logging without proving that `hdnts`, `hdntl`, and `/publish/.../<token>/...` values cannot reach logs or traces.

## Deployment

Do not deploy merely to verify a code change. Use `npx wrangler deploy --dry-run` unless the user explicitly requests a live deployment.

Before any real deployment, upload the required Worker secrets, set any account metadata in the shell or CI, and confirm:

- resource placeholders have private account-specific replacements;
- control and source-inspection paths are behind Access or equivalent policy;
- ingest paths have WAF/IP/rate controls;
- automatic URL logging is disabled or redacted;
- the target environment and custom domain are intentional;
- tests, type checks, build, and dry-run all pass.

## Known limitations

- The live demo has one stream and one 360p rendition.
- Primary/backup promotion is manual; automatic stale-source failover is not implemented.
- Seamless decoder continuity assumes aligned encoder timelines; arbitrary source sequence reconciliation is outside the demo.
- Application-level admin authorization is intentionally outside the demo code.
- Unit tests do not yet cover Workers bindings or the container runtime end to end.
- A project license must be selected before public release.
